# 05 的判断：MoE 和 hc 读的现成开关（开发机，2026-10-16）

数据来源是 `results/05-moe-hc-env.md`、`results/05-moe-hc-env/by-t.tsv` 和 `timing.tsv`，下面的数字都是开发机从这两个文件直接算的。
证据等级：✅ 已验证、⚠️ 推断、⬜ 未验证。8 段都开了 `STRATA_VERIFY_DEBUG=1`，都没开 `STRATA_MMVQ_Q6_SWAR`。
「默认」= 1-base、4-base、8-base 三段的平均；「加权」按 `analysis/03` 的生成窗口占比（T=1 12%、T=2 14%、T=3 12%、T=4 61%）。

## 1. 结论
1. ✅ **测量很稳**：三段默认的 GPU 中位数，每个 T 都在平均值 ±3 ms 以内（T=4：285.7、284.6、284.2 ms），加权差 ≤0.3%。
   这次没有看到 01、04 里的越跑越慢。下面 ≥3 ms 的差都超出了这个范围。
2. ✅ **5 个开关没有一个比默认快**。和默认相比的 GPU 中位数差（ms）：

   | 段 | T=1 | T=2 | T=3 | T=4 | T=6 | 加权 |
   |---|---:|---:|---:|---:|---:|---:|
   | 默认（ms） | 166.0 | 209.1 | 265.5 | 284.8 | 553.1 | 257.4 |
   | 2-split | +21.0 | +35.5 | +47.3 | +57.1 | +75.6 | **+18.8%** |
   | 3-lanes16 | −0.2 | +2.4 | +0.5 | +2.3 | +2.7 | +0.7% |
   | 5-lanes4 | +0.4 | −0.2 | +1.4 | −0.3 | −0.3 | 0.0% |
   | 6-hcdirect | +13.0 | +15.2 | +18.2 | +22.3 | +27.9 | **+7.6%** |
   | 7-hcnorm | +4.3 | +4.7 | +4.7 | +3.4 | +0.6 | +1.5% |

   - `STRATA_EXPERT_SPLIT=1` 每个 T 都慢，T=1（没有多 token 复用可言）也慢 21 ms，T 越大慢得越多。
     所以 ⚠️ 不能从这里推出「给 IQ2_XXS/IQ2_XS 补多 token 复用没用」：split 路径整体换了内核（每行 32 条 lane 等），慢的部分和复用无关。
   - MoE 每行 lane 数 4、8、16 结果相同（差都在 ±2.5 ms 内）。⚠️ 推断 MoE 内核的耗时不取决于每行的并行度。
   - hc 读的两个变体都比默认慢，默认（sliced down、split norm）就是现有里最快的。
3. ✅ 72 个请求 0 失败，没有崩溃文件。结论里列的 40 行「错误」都是 `captured the N-token window (upload no error, sync no error)`，
   是关键字误中，不是错误。
4. 生成 tok/s 不作结论（手册约定）：开了 DEBUG 后只有约 7 tok/s；默认三段每 token 136.5、127.8、132.8 ms，段间差比开关的差还大，
   而且接受率在 0.505–0.565 之间变动。

## 2. 对下一步的影响
- 只改环境变量的路走完了，**日常配置不用改**（这 5 个开关都不加）。
- 要继续提速 MoE 和 hc，只能改引擎。`analysis/04-moe-hc-code.md` 第 2 节剩下的候选：
  1. 默认路径给 IQ2_XXS/IQ2_XS 补 Multi（目标逐位相同）。
  2. hc 的 up 内核去掉 160 个工作组的重复计算（目标逐位相同）。
  3. hc 改用 q8（数值会变，要你决定）。
- ⬜ 这几项各自能省多少还不知道。按 `analysis/04` 第 3 节，先要有一个单独测 MoE 和 hc 读的工具，按 T、按类型拆开时间，再决定先改哪个。
