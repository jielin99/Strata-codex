# 11：140T 上 64 位寻址链接选项的代价（三个现成工具各编两种，不改引擎）

先读 `lab/README.md`，遵守共通规则、提交范围和推送步骤。全部用 CMD。
- 原始记录写到 `D:\dev\strata-lab\11-addr64\`（下文叫「原始目录」）。
- 结论写到 `lab/results/11-addr64.md`；可公开的数据文件放在 `lab/results/11-addr64/`（下文叫「数据目录」）。

**前提**：`plans/10` 已经执行完，引擎在 `d35f55e4`，`build-sycl-win\strata.exe` 是 33,721,856 字节、SHA256 以 `1a1e28c4` 开头。不是的话停下来报告。

**目的**：引擎链接时带 `-ze-opt-greater-than-4GB-buffer-required`。它要求内核能访问超过 4 GiB 的分配，编译器因此不能把能追溯到指针参数的访问
改成「分配起点 + 32 位偏移」的方式（从内存里读出的指针，例如专家权重的地址，本来就按 64 位访问）。开发机上去掉它，
引擎的 Q4_K、Q6_K 内核快 8–24%、保存的输出相同（`analysis/10-kern-ablate.md` 第 5 节），但开发机的比例不能推到 140T。这一份在 140T 上量出它的代价，
决定值不值得改引擎（依据 `analysis/11-prep.md`）。用三个现成工具，每个工具的目标文件只编一次、链接两次（只差这个选项）：
- `mmvq_lab`（`plans/02` 用过）：本模型稠密投影的 26 种（形状、类型），1–6 列（不含 24 个 2560×512 的 attn_k/attn_v 小投影）。
- `moe_probe`（`plans/09` 用过）：48 层 MoE（gate/up + SwiGLU + down），T=1–4 等。
- `gr_bench`（引擎自带的源码，`plans/07`、`08` 用过它的 CMake 版）：hc 读，T=1–6。

下文 `a64` = 带这个选项（和引擎相同），`a32` = 不带。这三个工具的每块显存分配都远小于 4 GiB，不带选项也读得对（`analysis/11-prep.md` 第 2 节）。
**引擎本身不能去掉这个选项**（专家缓存是一整块近 40 GiB 的分配），这一轮不改引擎、不改日常配置、不跑服务。

**例外**（README 共通规则的例外，仅限本手册写的步骤）：编译 `build-lab-a11`。

## 1. 编译（`build-lab-a11` 已存在时，先停下来问用户，不要覆盖）
```
set "VS2022INSTALLDIR=C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools"
call "C:\Program Files (x86)\Intel\oneAPI\setvars.bat" intel64 vs2022
set "E=D:\dev\Strata-intel-npu"
set "B=D:\dev\Strata-intel-npu\build-lab-a11"
set "L=D:\dev\Strata-lab140t\lab\tools"
mkdir %B%
mkdir %B%\a64
mkdir %B%\a32
set "CF=-fsycl -fsycl-default-sub-group-size=32 -fsycl-device-code-split=per_kernel /c /O2 /EHsc /std:c++20 /fp:precise /DNDEBUG -Wno-deprecated-declarations -Wno-unused-parameter -Wno-unused-variable"
set "CI=/I%E%\sycl\include /I%E%\include /I%E%\third_party\ggml /I%E%\sycl\src\kernels\cuda"
icx %CF% %CI% %L%\mmvq_lab.cpp /Fo%B%\mmvq_lab.obj
icx %CF% %CI% %L%\moe_probe.cpp /Fo%B%\moe_probe.obj
icx %CF% %CI% %E%\sycl\src\kernels\gr_bench.cpp /Fo%B%\gr_bench.obj
icx %CF% %CI% %L%\gpu_stamp_stub.cpp /Fo%B%\gpu_stamp_stub.obj
icx %CF% %CI% %E%\sycl\src\kernels\cuda\iq_kernels.dp.cpp /Fo%B%\iq_kernels.obj
icx %CF% %CI% %E%\sycl\src\kernels\cuda\native_mmvq.dp.cpp /Fo%B%\native_mmvq.obj
icx %CF% %CI% %E%\sycl\src\kernels\cuda\fused_gr.dp.cpp /Fo%B%\fused_gr.obj
set "L64=-fsycl -fsycl-device-code-split=per_kernel -Xsycl-target-backend=spir64 "-cl-fp32-correctly-rounded-divide-sqrt -ze-opt-greater-than-4GB-buffer-required""
set "L32=-fsycl -fsycl-device-code-split=per_kernel -Xsycl-target-backend=spir64 "-cl-fp32-correctly-rounded-divide-sqrt""
icx %L64% %B%\mmvq_lab.obj %B%\iq_kernels.obj %B%\native_mmvq.obj -o %B%\a64\mmvq_lab.exe
icx %L64% %B%\moe_probe.obj %B%\iq_kernels.obj %B%\native_mmvq.obj -o %B%\a64\moe_probe.exe
icx %L64% %B%\gr_bench.obj %B%\fused_gr.obj %B%\gpu_stamp_stub.obj -o %B%\a64\gr_bench.exe
icx %L32% %B%\mmvq_lab.obj %B%\iq_kernels.obj %B%\native_mmvq.obj -o %B%\a32\mmvq_lab.exe
icx %L32% %B%\moe_probe.obj %B%\iq_kernels.obj %B%\native_mmvq.obj -o %B%\a32\moe_probe.exe
icx %L32% %B%\gr_bench.obj %B%\fused_gr.obj %B%\gpu_stamp_stub.obj -o %B%\a32\gr_bench.exe
```
以每条命令退出码为 0、6 个 exe 都存在为准；每条命令的耗时、6 个 exe 的大小和 SHA256 记进原始目录的 `build.txt`。
`a64` 和 `a32` 的同名 exe 的 SHA256 应该不同（链接选项不同）；相同的话停下来报告。失败就把报错原文写进结论，停止。
